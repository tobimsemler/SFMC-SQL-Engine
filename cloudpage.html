What this is

This page embeds a small, dependency-free JavaScript SQL engine that reimplements the read-only SQL dialect used by Salesforce Marketing Cloud's Query Studio (the SQL that runs inside a Query Activity). It parses and evaluates SELECT statements against CSV data you upload yourself; it never connects to Marketing Cloud and never writes anything back.

Not affiliated with or endorsed by Salesforce. "Salesforce Marketing Cloud" and "SFMC" are trademarks of Salesforce, Inc. This reference describes documented, publicly known behavior of Query Studio's SQL dialect (Microsoft SQL Server T-SQL, restricted to a read-only subset) for learning purposes.

Statement structure

Query Studio (and this engine) only ever runs a single SELECT statement, optionally preceded by one or more Common Table Expressions. There is no AST/grammar for INSERT, UPDATE, DELETE, MERGE, DDL, or stored procedure calls. Marketing Cloud enforces this because a Query Activity's job is to populate a target Data Extension by reading, never to mutate source data extensions.

[ WITH cte_name [ (col1, col2, ...) ] AS ( SELECT ... ) [, ...] ]
SELECT [ DISTINCT ] [ TOP (n) [ PERCENT ] ]
    column_list
FROM source [ alias ]
[ INNER | LEFT [OUTER] | RIGHT [OUTER] | FULL [OUTER] | CROSS ] JOIN source [ alias ] [ ON condition ]
[ WHERE condition ]
[ GROUP BY column_list ]
[ HAVING condition ]
[ ORDER BY column_list [ ASC | DESC ] ]
[ UNION [ ALL ] SELECT ... ]

SELECT clause

  • SELECT *, SELECT alias.*, or an explicit, comma-separated column list.
  • DISTINCT removes duplicate output rows (compared across all selected columns).
  • TOP (n) and TOP (n) PERCENT limit the row count of the *final* result, after ORDER BY. n must be a literal number, not an expression or a subquery.
  • Column aliases: expr AS alias or the bare form expr alias. Aliases are needed for computed/aggregate columns if you want to reference them elsewhere (e.g. in ORDER BY by name or ordinal position).

FROM and JOIN

  • Sources are Data Extension names, optionally schema-qualified (e.g. ENT.SharedDataExtension), each with an optional alias.
  • Join types: INNER JOIN, LEFT [OUTER] JOIN, RIGHT [OUTER] JOIN, FULL [OUTER] JOIN, CROSS JOIN. Marketing Cloud's documented guidance caps a query at a limited number of joined objects; this engine enforces the same idea via a configurable maxJoins limit (default 8).
  • Derived tables (a subquery in the FROM/JOIN position, e.g. (SELECT ...) AS x) are supported and must be aliased.
  • Scalar and correlated subqueries (a SELECT nested inside an expression, or inside IN (...)) are not supported by Query Studio's engine; rewrite them as a JOIN. This engine raises an explicit error pointing you at that rewrite instead of silently misbehaving.

WHERE, HAVING and predicates

  • Comparison operators: =, <> (or !=), <, <=, >, >=.
  • Logical operators: AND, OR, NOT (standard T-SQL precedence: NOT binds tighter than AND, which binds tighter than OR).
  • IS [NOT] NULL, [NOT] LIKE pattern [ESCAPE char], [NOT] IN (value, value, ...), [NOT] BETWEEN low AND high.
  • LIKE wildcards follow T-SQL: % (any run of characters), _ (any single character), [set] and [^set] character classes.
  • HAVING filters after GROUP BY/aggregation, exactly like standard SQL: you cannot filter on an aggregate result in WHERE.

GROUP BY / ORDER BY

  • GROUP BY accepts a comma-separated list of expressions/columns.
  • ORDER BY accepts column names, expressions, aliases, or 1-based ordinal positions (ORDER BY 2 DESC). Each term takes an optional ASC/DESC (default ASC).
  • After a UNION, ORDER BY applies to the combined result and must appear only after the final SELECT, not on an individual branch.

CASE, CAST and CONVERT

  • Both simple (CASE expr WHEN v THEN ... END) and searched (CASE WHEN cond THEN ... END) forms, with an optional ELSE.
  • CAST(expr AS type) and CONVERT(type, expr [, style]) follow SQL Server's type names (e.g. VARCHAR, INT, DECIMAL(p,s), DATETIME) and numeric date style codes (e.g. 101 = MM/DD/YYYY, 103 = DD/MM/YYYY, 120-style ISO forms).

Aggregate functions

FunctionNotes
COUNT(*) / COUNT(expr) / COUNT(DISTINCT expr)COUNT(expr) ignores NULLs; COUNT(*) counts all rows in the group.
SUM, AVGIgnore NULLs; empty/all-NULL input to SUM yields NULL, matching T-SQL.
MIN, MAXWork across numbers, strings, and dates using the same comparison rules as ORDER BY.
STDEV, STDEVP, VAR, VARPSample vs. population variants, exactly as in T-SQL.

Window functions

ROW_NUMBER(), RANK(), DENSE_RANK(), and NTILE(n) are supported, each requiring an OVER (...) clause with an optional PARTITION BY and a required/optional ORDER BY depending on the function, matching T-SQL's rules, since aggregates used as window functions (e.g. SUM(x) OVER (...)) are not part of Query Studio's supported surface and are rejected here too.

DATEADD clamps at month-end boundaries the same way SQL Server does (e.g. adding a month to Jan 31 lands on Feb 28/29, not Mar 3). DATEDIFF counts boundary crossings, not elapsed duration: one minute past midnight counts as a full day of difference from the prior evening, exactly like T-SQL.

Known Query Studio restrictions this engine mirrors

  • No INSERT/UPDATE/DELETE/DDL: read-only by grammar, not by permission check.
  • No scalar or correlated subqueries in SELECT/WHERE/IN (...): rewrite as a JOIN.
  • A maximum number of joined sources per query (configurable; defaults to 8 here).
  • Only one statement per query: trailing statements after a terminating ; are rejected.
  • Unicode identifiers are allowed unquoted (e.g. a field called Købsdato), matching how Automation Studio and Query Studio treat non-ASCII Data Extension/field names.

Differences from a full T-SQL Server engine

This is a client-side reimplementation, not Microsoft SQL Server. It supports the practical subset above; it does not implement stored procedures, transactions, temp tables, cursors, triggers, permissions, or SQL Server system views/functions beyond what's listed here.
